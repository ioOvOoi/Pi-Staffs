# Verification Planning（验证计划）

先写好证据路径，再动手改代码。

## 流程

1. 把主张拆成可证伪的句子：「派发失败会重试同一模型」而不是「派发更稳了」。
2. 为每条主张选**最小的**验证手段：单测 / 项目测试 / 定点探针 / 手工复现命令。优先能自动跑的。
3. 写清预期结果与失败长什么样（错误文本、退出码、计数），避免「跑一下看看」。
4. 只有一条主张特别贵时才升级到整包构建；能一行命令证明的绝不跑全套。
5. 实现完先跑这些检查；失败就查原因再改，不要原样重跑。

## 交付格式

任务里固定写三段：`主张 / 证据命令 / 期望输出`。跑完把真实输出贴回来，别只写「已通过」。
