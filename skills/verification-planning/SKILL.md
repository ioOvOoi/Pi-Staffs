# 验证计划（Verification Planning）

## 建立一条证据路径

在改动一个非平凡系统之前，先建立**证据路径**：从「你要主张的结论」到「能确立、限制或反驳它的证据」之间，一条本项目特有的路线。

目的不是挑一个熟悉的技术手段，而是决定：**这个系统要怎样才能把这次改动的真相揭示出来**。

## 1. 先把主张说清

写出需要变成事实的那个行为，以及「哪些条件会让这个结论其实是错的」。

想清楚：什么必须改变、什么必须保持不变、行为在哪里跨越边界、哪一种失败最要命。

**完成标志：** 主张、其中真正的不确定性、以及重要的失败模式，都具体到可以着手调查。

## 2. 设计证据路径

从系统自身推导出可行的证据路径：可控输入、可观测效果、状态迁移、不变量、边界、产物，以及「能否重复或回退一个场景」的能力。

先列出多个候选再选：优先那条**可信度足够而代价（成本、风险、工作量）相称**的路径。

**完成标志：** 有一条首选路径、清楚它的局限，并且当情况变化时还有一条更弱或更强的备选。

**本项目可用的证据路径（按可信度排序，随手取用）：**

| 路径 | 何时够用 | 命令 / 做法 |
| --- | --- | --- |
| 契约冒烟 | 插件/扩展的行为与注入面 | `npm run smoke`（不启动 Pi） |
| 类型检查 | 签名、类型、导入面 | `npm run typecheck` |
| 定向单元探针 | 纯函数、解析、状态机 | 在 `fabric_exec` 里直接跑最小输入 |
| 真宿主试跑 | 只有真实加载才能暴露的问题 | 交互式 Pi 里 `/reload` + `/staffs`（print 模式不执行斜杠命令） |
| 端到端行为 | 派发/重试/面板等跨进程行为 | `staffs.run` + 看 `.staffs/state.json` 与回执 |
| 人工观察 | 无自动判定（TUI、视觉） | 截图 / 让用户确认 |

## 设定验证预算

在最终状态时：列出彼此独立的主张，每个主张指定一个负责人去确立或反驳，然后选**最小且不重复**的证据集覆盖这些主张与重要边界。复用旧证据的前提是相关的代码、输入、环境与状态仍然有效。仓库与发版要求的检查照旧执行；只有当出现明确条件时才展开或重跑验证。

## 3. 必要时做一个「验证抓手」（verification affordance）

当现有系统让决定性的真相太间接或太模糊时，用**验证抓手**扩展证据路径：它是让相关状态变得**可控、可观测、可重复、可诊断**的最小能力。

问自己：什么能力能让一个 agent 直接确立主张、从已知状态重放场景、并且无需推测就解释失败？优先选能增强直接性、确定性、agent 可读性、隔离性、可重置性或未来复用性的抓手。

把抓手当作证据路径的一部分，而不是顺手做的产品特性。动手前先明确决定它是临时的还是长期的。

**完成标志：** 选定的路径能按风险等级足够直接地确立主张，且需要的抓手有明确的生命周期。

## 4. 路径未知时先做研究

当正确的证据路径取决于陌生的依赖、框架、外部服务或快速变化的能力时，先派 `librarian` 做聚焦调研（`staffs.run({ role: "librarian", task: "…" })`），再定方案。

要问的是：官方或项目特定的设施、约束与取舍——特别是那些直接影响这次验证问题的部分。如果项目里已有的证据能直接解决选择，就不要外求。

**完成标志：** 选定的路径建立在已知能力与真实约束之上，而不是假设之上。

## 5. 让路径可跑

只准备「可靠走完证据路径」所需的支撑，并且保持它狭窄、可重复、可安全检视。

决定这份支撑是长期价值还是只为解决当前不确定：有长期价值的要明确保留；临时支撑在达成目的后移除。

要引入依赖、常驻诊断面，或纯粹为收集证据而做结构性改动时，先问过用户。

**完成标志：** 走完这条路径不需要在环境、状态或结果解释上做任何猜测。

## 6. 关闭证据路径

实现之后，按计划走完路径，把得到的证据对照原始主张解释。

报告主张是**被确立、被限制、还是被反驳**；把已知事实与仍然存在的不确定性分开说。

**完成标志：** 未来的读者能看到「结论由什么支撑」以及「哪里超出了证据能覆盖的范围」。

## 适用范围

按比例使用本技能。小型的机械改动直接走常规检查即可；大型多阶段工作则让本技能先确立证据路径，后续工作按它走。

## 与 omo-slim 原版的差异

- 原版让 `@librarian` 调研；本插件里 `librarian` 通过 `staffs.run({ role: "librarian" })` 派发。
- 原版引用的仓库/发版检查由各自的 `AGENTS.md` 定义；本仓库对应 `npm run typecheck` + `npm run smoke`。
- 其余章节、完成标志与判据均按原文保留。
