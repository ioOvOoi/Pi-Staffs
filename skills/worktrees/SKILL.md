# Worktrees（隔离车道）

主仓库永远保持可交付；不确定的活放到 worktree 里做。

## 流程

1. 建车道：`staffs_worktree({ op: "add", name })` → 返回的路径就是这条车道的根目录。
2. 派发时把该路径写进任务描述，明确「只在此目录内改动」。
3. 车道内跑自己的构建与测试，不依赖主仓库的未提交状态。
4. 集成：在主干上 review diff（配合 `staffs_review`），只挑要的部分合入；不要整支车道无脑 merge。
5. 收尾：`staffs_worktree({ op: "remove", name })`；未被采纳的改动要明确说明丢弃原因。

## 红线

- 车道里禁止 `git push`、禁止改 `.git` 配置。
- 主仓库同一时刻只允许一个写者；需要并行就先分车道。
- 依赖安装只在车道内做，别污染宿主环境。
