# Loop Engineering（循环工程）

循环的价值取决于判据是否可自动判定。判据含糊就先访谈，别开循环。

## 1. Grill（先把判据问清楚）

- 目标是什么？循环成功时世界变成什么样？
- 判据类型：`command`（成功命令）/ `test` / `build` / `lint` / `fileExists`（产物路径）/ `oracle`（另一个模型审阅）/ `manual`（人工确认）。
- 上限：最多几轮、最多几次派发、超时多少。

## 2. Run（循环）

1. `staffs_goal` 写入判据（这是压缩后还能恢复的唯一凭据）。
2. 每轮：派发实现/修复 → 跑判据命令 → 记录真实输出。
3. 判据通过即停；连续两轮无进展就停并交回用户，而不是换着法子重试。
4. 到上限仍未通过：如实汇报「卡在哪一条判据、失败输出是什么、已尝试哪些思路」。

## 3. Monitor（观察）

- `staffs_board` 看每轮 attempts：谁在重试、退避多少、是否被判定 stalled。
- 同一模型连续失败要换人（切档位或换角色），不要无脑加轮次。
