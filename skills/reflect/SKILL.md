# Reflect（复盘）

这套流程只做一件事：把重复的摩擦变成一条可复用的资产，或者明确说明不需要改。

## 流程

1. 取材：最近的会话记录、`.staffs/state.json` 里的 attempts（谁重试多、谁总失败）、项目笔记里的坑。
2. 找重复：同一类问题出现 ≥2 次才算模式，单次偶发不立项。
3. 选最小载体：一条技能 / 一个 `/staffs` 子命令 / 一条角色提示 / 一处配置 / 一段文档。
4. 落地并留下判据：写清「下次满足什么条件就该触发它」。
5. 明确说「不改」的情形：一次性问题、已有机制覆盖、改动收益低于维护成本。

## 红线

- 一次只改一处；不要顺手重写配置或角色矩阵。
- 基于证据（日志、attempts、失败文本）而不是印象下结论。
