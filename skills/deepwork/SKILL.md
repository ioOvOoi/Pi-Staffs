# Deepwork（深工编排）

只在「一次聊不完、做错代价高」的活上开这套流程。判据：阶段之间有依赖、不能分片交付、或需要两条以上专才车道并行。

## 流程

1. **立契约**：用 `staffs_goal` 写清目标与验收标准（每条都要可被命令或测试证明）。
2. **拆阶段**：用 `staffs_task add` 建 DAG，每条任务写明「谁做（role）+ 交付物 + 验收」。依赖用 `deps` 串起来，别靠口头记忆。
3. **排车道**：`staffs_board` 看就绪集；能并行的用 `staffs.run({ spawn: true })` 开后台车道，写同一批文件的活必须串行（单写者）。
4. **派发**：`staffs.run({ role, task })`。不要在派发点指定 model/thinking/tools——那是档位与角色矩阵的职责。
5. **过闸**：每个阶段结束先 `staffs_review`（干净上下文复审）再 `staffs_task finish`。blocker/major 没清完不许进入下一阶段。
6. **收尾**：汇总 attempts 里的重试与降级，检查验收标准逐条打勾，最后 `staffs_task list` 确认没有半成品留在 DAG 里。

## 红线

- 不跳阶段验收；不把「我读过了」当成证据。
- 车道写冲突时停下来问用户，而不是猜谁优先。
- 上下文被压缩后先用 `staffs_board` 与 `staffs_goal` 恢复判据，再继续动手。
