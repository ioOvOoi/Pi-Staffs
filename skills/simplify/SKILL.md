# Simplify（简化）

判据只有一个：新同事会不会比原来更快看懂？行数减少不是目标。

## 流程

1. 先固定行为：有测试就跑测试；没有就先用最小探针钉住当前行为，否则「行为不变」无从谈起。
2. 找复杂度来源：嵌套分支、重复条件、反复传递的参数包、能算出来却存下来的状态、为「将来可能需要」而留的开关。
3. 一次只做一类简化，改完立刻验证。
4. 把重复 3 次以上的逻辑提成命名函数；只出现 1 次的抽象不要提。
5. 删掉自己制造的死代码；别人留下的死代码先问再删。

## 红线

- 不改公共接口签名、不动错误语义、不动日志里被依赖的文本。
- 顺手重构未损坏的模块是禁止项——那会让复审无从下手。
